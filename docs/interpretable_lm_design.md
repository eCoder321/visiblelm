# Designing a Language Model With Visibility Into How Its Behavior Forms

*A first-principles design, built and tested on a small language model. September 9, 2026.*

---

## 0. The goal, restated

We want a neural network where the answer to **"why did it produce this output?"** is not a probe, a post-hoc story, or a chain-of-thought it chooses to emit — but the computation itself, read off in a vocabulary a human can inspect.

Concretely, "visibility into how behavior is formed" means four properties must hold **at once**:

| # | Property | Operational test |
|---|---|---|
| P1 | **Faithful** — the legible representation *is* the causal path, not a parallel description | Ablating the features that the explanation names must change the output; ablating others must not |
| P2 | **Legible** — intermediate states are expressed in a small, fixed set of nameable units | Each unit corresponds to one identifiable concept (measured against ground truth where we have it) |
| P3 | **Complete** — no dense side channel the "real" computation can route around | All information crossing a layer is carried by the legible units, by construction |
| P4 | **Compositional** — the output decomposes into contributions of the units, and units decompose into earlier units | Additive attribution; a traceable causal graph from input to logit |

The reason these matter (from the previous discussion): behavioral checking can never cover every input. To trust behavior on *untested* inputs we need to know the mechanism that produces it. Ordinary transformers make the mechanism illegible in three specific ways — dense superposed residual streams, no fixed vocabulary of internal states, and no guarantee that any legible signal (like chain-of-thought) is on the causal path. The design below attacks exactly those three.

---

## 1. First-principles derivation of the design

Start from what a language model must do: map a context to a next-token distribution through a sequence of layers. Every design decision below is forced by one of P1–P4.

**D1. The interface between layers must be a sparse code over a fixed dictionary (P2, P3).**
Dense vectors in superposition are unreadable because one dimension carries many meanings and one meaning is spread over many dimensions. Replace the residual stream at every layer boundary with a **top-k, non-negative code** over a dictionary of unit-norm "feature" directions. A position's state is then "these k features, with these strengths." The dictionary is the vocabulary. There is no bypass — the decoded code is the *only* thing the next layer sees.

**D2. The embedding must also be a code (P3).**
Otherwise the input enters through a dense channel. So the first bottleneck sits right after token+position embedding.

**D3. The readout must be linear in the final code (P4).**
`logits = code · W`. Every logit is then an exact sum of per-feature contributions. No nonlinearity after the last bottleneck.

**D4. Encoder and decoder must be tied (P2).**
If a feature has one direction for reading and a different one for writing, it has two meanings. Tied weights force one direction = one meaning.

**D5. Faithfulness must be measured by intervention, not correlation (P1).**
The explanation names features; the test ablates them. If the top-attributed features are both *necessary* (ablate → prediction collapses) and *sufficient* (keep only them → prediction survives), the attribution is the mechanism.

**D6. Legibility must be measured against ground truth (P2).**
Real text has no ground truth for "what a feature should mean." So the primary testbed is a **synthetic language with known latent causes**, where we can compute exactly how well each feature tracks each true variable. Real text is the secondary testbed, to confirm the design trains a real LM.

Everything else — attention, MLP, layer norm — stays standard, because the *interface* is what we're making legible. (Section 5 discusses why the *transformation* inside a block is the remaining hard problem.)

## 2. Testbeds and metrics

### 2.1 Synthetic language (ground-truth causes known)
- Vocab: 4 mode tokens + 12 content tokens. Sequence = mode token, 2 random content tokens, then 13 tokens generated by the mode's rule:
  - mode 0 **repeat**: x[t] = x[t−1] · mode 1 **succ**: x[t] = x[t−1]+1 · mode 2 **copy2**: x[t] = x[t−2] · mode 3 **pred**: x[t] = x[t−1]−1
- Every prediction from t ≥ 2 is deterministic given (mode, last 1–2 tokens). Irreducible entropy (the 2 random tokens) ≈ **0.205 nats/token** — this is the floor any model can reach.
- Ground-truth predicates per position: `mode=m`, `cur=v`, `prev=v`, `prev2=v`, `next=v`, `pos=t`, and `mode=m & cur=v` (the true cause of the next token).

### 2.2 Real text
- Character-level Tiny Shakespeare (65 chars), 64-char windows, 60k training windows, 3000 steps. Same architecture, scaled: d=96, 3 layers, dictionary 384, k=12.

### 2.3 Metrics (all computed on held-out data)
- **Tax**: eval NLL vs a dense transformer of identical size.
- **Faithfulness**: at a random position, rank active final-layer features by contribution to the target logit. Report target log-prob after (a) ablating the top-3, (b) ablating 3 random active features, (c) keeping *only* the top-3. Faithful ⇔ (a) ≪ (b) and (c) ≈ baseline.
- **Completeness**: fraction of the target logit explained by its top-3 features (median).
- **Legibility**: for each live feature, best F1 against any single ground-truth predicate. Report median and the fraction of features with F1 > 0.8 ("clean").
- **Dead features**: fraction of dictionary never used.
- **Layer invariance**: with a shared dictionary, does feature *f* get the same best-predicate label at every layer?
- **Circuit trace**: recursive single-node ablation from the top final feature back to embedding features. Effect = drop in the child feature when the parent is ablated. Tractable *because* only k nodes are active per position.

Implementation: JAX/Optax, CPU. Code in `itlm.py` (model/training), `analyze.py` (metrics/tracing), `analyze_text.py`.

## 3. Iterations: what was built, what was measured, what changed

### v0 — Dense baseline (control)
Standard tiny transformer (d=64, 2 layers, 2 heads). Synthetic eval NLL **0.2058** — hits the floor. Nothing to interpret.

### v1 — Sparse bottleneck at every layer boundary (D1–D4)
Dictionary 128, k=8, shared across layers, tied encoder/decoder, linear readout.

| metric | v1 |
|---|---|
| eval NLL | **0.2053** (tax: none) |
| dead features per bottleneck | 45% / 32% / 24% |
| ablate top-3 / random-3 / keep-only-top-3 (Δ log-prob) | **−1.73 / −0.22 / −0.035** |
| completeness (top-3) | 0.62 |
| clean final features (F1>0.8) | 9% (median F1 0.49) |

**Findings.**
- The bottleneck costs nothing on this task: the model still reaches the entropy floor.
- **Faithfulness passes.** The top-3 attributed features are ~8× more necessary than random active ones, and *sufficient* on their own (keeping only 3 of 8 features loses 0.035 nats). The attribution is the mechanism.
- The model spontaneously discovered features that are exactly the true causal variables: e.g. feature 1 = `mode=repeat & cur=10` with F1 = **1.00**, feature 111 = `mode=pred & cur=9` with F1 = 1.00.
- But only 9% of live features are that clean; a quarter to nearly half are dead.
- Per-layer dictionaries (not shared) gave equivalent numbers — sharing is free here.

**Bugs found.** (1) The anti-dead-feature auxiliary loss was written on `(code > 0)`, which has zero gradient — it was a no-op. (2) Late-training divergence at constant LR; fixed with warmup + cosine decay + gradient clipping.

### v2 — Differentiable AuxK loss for dead features
Features unused in a batch are asked to reconstruct the bottleneck's residual error (gradient flows to them; they compete back in).

| metric | v1 | v2 (k=8) | v2 (k=4) |
|---|---|---|---|
| eval NLL | 0.2053 | 0.2216 | 0.2123 |
| dead (layer bottlenecks) | 32% / 24% | **4% / 9%** | 5% / 34% |
| ablate top / random / keep-only | −1.73 / −0.22 / −0.035 | **−8.45 / −1.08 / −0.012** | −4.45 / −2.27 / −0.002 |
| completeness (top-3) | 0.62 | **1.10** | 1.09 |
| clean final features | 9% | **19%** (median 0.62) | 19% (median 0.61) |

**Findings.**
- Dead features nearly eliminated; clean features doubled; 3 features now explain ≥100% of the target logit.
- Sparser k=4 did **not** improve legibility and made random ablations far more damaging — with fewer slots each feature is more load-bearing, so the model packs more meaning into each. Sparsity alone is not the lever.

### The circuit trace works — and exposes a design flaw
Recursive ablation on v2 for the copy-2 mode, predicting token 10 at position 9:

```
bn2 pos8 f8  act=8.96  [next=10]
  (effect 8.96) bn1 pos8 f8   act=5.32 [next=10]        <- same feature carried forward
  (effect 0.75) bn1 pos8 f26  act=2.15
      (effect 2.15) bn0 pos1 f58 [cur=10]               <- attention read token 10 at
      (effect 0.91) bn0 pos3 f58 [cur=10]                  the same-parity positions:
      (effect 0.71) bn0 pos5 f58 [cur=10]                  the period-2 mechanism, readable
```
For the succ/pred modes the trace reaches **position 0 (the mode token)** via attention — the mechanism "look up the rule, apply to current token" is visible in the graph.

But labeling features per layer revealed: **sharing the dictionary does *not* make a feature mean the same thing at every layer.**

| model | features with the same label at every layer |
|---|---|
| v1 | 23% |
| v2 | **3%** |

Why (first principles): a shared dictionary shares *directions*, not *meanings*. Each block can rewrite the residual arbitrarily and the next bottleneck re-encodes it from scratch, so a direction is free to be reused for a different concept at a different depth. AuxK makes it worse by putting more features in play.

### v3 — Code-space residual (persistence by default)
Keep the residual stream *in code space*. Each block reads `decode(code)`, computes a dense update, projects it onto the dictionary, keeps only the `k_write` largest-magnitude entries (a sparse **signed write**), and the new code is `topk(relu(code + Δ))`. A feature now persists unless a layer explicitly writes against it, and **each layer's contribution is itself a readable sparse diff.**

| metric | v2 | v3 (k_write=8) | v3 (k_write=4) |
|---|---|---|---|
| eval NLL | 0.2216 | **0.2069** | 0.2640 |
| dead (layer bottlenecks) | 4% / 9% | 12% / 5% | — |
| ablate top / random / keep-only | −8.45 / −1.08 / −0.012 | −2.79 / −0.70 / −0.003 | −3.71 / −1.29 / −0.116 |
| completeness (top-3) | 1.10 | 0.86 | 0.95 |
| clean final features | 19% | 7% | **27%** |
| same label at every layer | 3% | **27%** | **56%** |

**Findings.**
- Persistence works: layer invariance 3% → 27% → 56% as writes are restricted.
- `k_write` is a clean, interpretable dial: *how much is each layer allowed to change?* Restricting it buys legibility and invariance at the first real perplexity cost (0.264 vs floor 0.205 at k_write=4).
- Final-layer features remained polysemantic on the output side: labels like "next=5 *or* next=7 depending on mode" — a feature votes for several tokens and other features disambiguate. The linear readout *permits* this.

### v4 — Sparse readout (each feature may vote for at most *m* tokens)
Replace `logits = code · W` with `logits = code · top-m-per-row(R)`. A final feature is then, by construction, "predict one of these m tokens." First attempt failed to train (NLL stuck at 2.29): a hard top-m mask starves every entry outside the top-m of gradient, so they can never compete in. Fixed with a straight-through estimator (sparse forward pass, dense gradient).

**Result: negative.** With m=2, neither the hard mask nor the straight-through version left the uniform-prediction plateau within 1500 steps (eval NLL 2.29 and 2.49; ln 12 = 2.48). With only 2 votes per feature and 8 active features, the learning signal about *which* token to predict reaches the model through ≤16 logit entries, and until a feature's top-2 happens to include the right token there is no useful gradient for the rest of the network. A workable version needs a curriculum (start dense, anneal m down) or a larger m — I did not have budget to test that, so **the design below uses v3 (linear readout), and v4 is recorded as an open item.**

## 4. Real text: does the design train an actual (small) language model?

Character-level Tiny Shakespeare, 64-char context, ~0.4M parameters, 3000 steps on a single CPU core.

| model | eval NLL (nats/char) | bits/char | notes |
|---|---|---|---|
| dense baseline (d=96, 3 layers) | **1.633** | 2.36 | control |
| v2 bottleneck (dict 384, k=12, AuxK) | **2.029** | 2.93 | still improving at step 3000 (2.20→2.14→2.04→2.02 over the last 1500 steps) |
| v3 (code-space residual, k_write=12) | **2.269 @ step 1000** (run in progress) | 3.27 @ step 1000 | like-for-like: v2 was 2.340 and dense 1.866 at step 1000; v3 is learning ~0.07 nats ahead of v2 at every logged step (2.438 vs 2.534 @500) |

**Findings on real text (v2, held-out windows).**

| metric | value |
|---|---|
| dead features per bottleneck (emb / L1 / L2 / L3) | 45% / 6% / 2% / 0% |
| ablate top-3 / random-3 / keep-only-top-3 (Δ log-prob from base −2.23) | **−10.39 / −3.00 / −1.96** |
| completeness (top-3 features' share of target logit, median) | **1.18** |
| features with best-F1 > 0.8 vs hand-written char predicates | 5% (emb) · 2% · 2% · 4% (final) |

1. **The interpretability tax is real on text: +0.40 nats/char (2.93 vs 2.36 bits/char)** at equal parameter count and steps. The v3 code-space residual narrows it: at matched steps it trails the dense model by 0.40 nats where v2 trailed by 0.47, and it is ahead of v2 at every logged step — so making persistence the default costs *nothing* on text and helps optimization, the same pattern seen on synthetic data. Part of it is convergence speed (the bottleneck model was still improving ~0.1 nats per 500 steps when stopped), part is capacity: 12 active features out of 384 is a far narrower channel than a 96-dim dense residual. On the synthetic task the channel was wide enough; on text it is not. This is the cost the design makes *visible* instead of hidden.
2. **Faithfulness transfers.** The 3 features named by the attribution are 3.5× more necessary than random active features, and keeping *only* them makes the prediction slightly *better* than using all 12 (the other 9 add noise). Three features explain 118% of the target logit. The explanation is still the mechanism.
3. **Legibility against hand-written predicates is weak** — but the clean features that do exist are unmistakable: at the embedding, separate features for `cur=' '` (F1 0.97), `cur='t'` (0.92), `cur=','` (0.92), `cur='a'`, `cur='\n'`; at the final layer, a cluster of *distinct* features that all fire on `cur=' '` (F1 0.88–0.97), i.e. "at a word boundary" split into several sub-cases the predicate set can't tell apart. This is the limitation of D6 on real data: without ground truth we can only score features against concepts we thought to write down, and most of what a text model represents (word identity, syntactic state, speaker turn) is not in that list. The features are probably more legible than the number says; the *measurement* is the bottleneck.

## 5. What was learned (the honest summary)

**Confirmed by measurement**
1. Forcing every layer boundary through a sparse dictionary bottleneck is **free on the synthetic task** and costs **+0.4 nats/char (2.93 vs 2.36 bits/char)** on real text at this scale — a real, visible tax.
2. **Faithfulness is achievable by construction.** In every bottleneck model, the 3 features the attribution names are both necessary and sufficient for the prediction. This is the property probes and chain-of-thought lack.
3. **The model learns the true causal variables as features** when they exist (F1 = 1.00 on `mode & current token`), without being told what they are.
4. **Mechanisms are traceable as a sparse causal graph** — the "look up the rule at position 0" and "attend to same-parity positions" mechanisms are readable from single-node ablations, which is tractable only because k nodes are active per position.

**Negative results (as valuable as the positives)**
5. **Sparsity alone does not buy legibility.** k=4 vs k=8: no gain, and features became more overloaded.
6. **A shared dictionary does not give features stable meaning across depth** unless the architecture makes persistence the default (v3). "Same direction" ≠ "same meaning."
7. **Every legibility constraint has a gradient-flow failure mode**: the non-differentiable usage loss (silent no-op) and the hard top-m readout (starved gradients). Interpretability-by-construction is largely an exercise in making hard constraints trainable.
8. **Legibility and capacity trade off on a dial** (`k_write`), and the trade is visible in the numbers rather than hidden.

**What remains opaque — and why it's the real problem**
9. The *interface* between layers is now legible and faithful. The *transformation* inside a block (attention + MLP mapping k input features to k_write output features) is still a dense function. We can attribute it by ablation (which input features cause which written features), but we cannot yet *read* it as a rule. A full solution needs the block itself to be a composition of legible operations — e.g. attention that routes *features* rather than dense values, and an MLP replaced by a sparse feature→feature lookup. That is the next design target, and it is where the capacity cost will really bite.
10. Ground truth is what made this measurable. On real text we can only score features against hand-written predicates (current/next/previous char, vowel, space…), which is a weak proxy. Scaling this design means scaling the *evaluation* — automated feature labeling and held-out mechanism tests — not just the model.

## 6. The design, as it stands (v3/v4 spec)

```
tokens ──embed──▶ bottleneck₀ ──▶ code₀ (k active features over shared dict D)
for each layer l:
    h      = code_l · D                         # decode (the only input the block sees)
    upd    = Attn(LN(h)) + MLP(LN(h + Attn))    # standard block, dense internally
    Δ      = top_{k_write}( upd · Dᵀ + b_l )    # sparse SIGNED write in feature space
    code_{l+1} = top_k( relu(code_l + Δ) )      # persistence by default
logits = code_L · W                             # linear readout (exact per-feature attribution)
# (v4 sparse per-feature readout: desirable, not yet trainable — see §3)
```
Losses: next-token NLL + AuxK (dead features reconstruct residual error). Dictionary rows renormalized to unit length after every step. 

Everything a human needs to read a decision is on the causal path: which features were active at each position, which features each layer wrote, and which of those features voted for the output token — and each of those can be verified by ablation.
