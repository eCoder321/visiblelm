## 1. What the project is (my understanding)

**Origin.** The chat began with "why can't labs align AI?" and narrowed to one claim: we can only check behavior, not internals. The previous session correctly retracted that as a maturity limit rather than a principle, then derived that *checking behavior on untested inputs requires knowing the mechanism*. That turned the question into a design problem: build a network whose mechanism is readable by construction.

**Goal (P1–P4).** Faithful (the readable representation is the causal path), Legible (states are nameable units), Complete (no dense side channel), Compositional (outputs decompose into units, units into earlier units).

**Design lineage.**
- v1: top-k non-negative code over a shared tied dictionary at every layer boundary, including the embedding; linear readout.
- v2: AuxK loss so dead features get gradient.
- v3: the residual lives in code space; each layer writes a sparse signed delta of size `k_write`; persistence by default.
- v4: sparse per-feature readout. Did not train. Parked.

**Evidence so far (single seed everywhere).**
- Synthetic task: no perplexity tax; ablating top-attributed final features hurts far more than random; some features match ground-truth causes with F1 = 1.0; most features are not clean; dead features are common; a shared dictionary does not give stable meaning across depth, and v3 partially fixes that at a capacity cost.
- Text (char-level Shakespeare): +0.4 nats/char tax; the same ablation pattern holds; legibility vs hand-written predicates is weak; the v3 text run died at step 1000.

**Plan agreed with you.** Replace the dense block with rules (`IF few features THEN write few features`) and lookup routing with provenance, keep persistence, train by annealing dense to sparse and snapping to a hard rulebook, verify hard reproduces soft. Add open Ω, intervention-defined legibility, anti-smuggling audits, multi-seed replication. Phases 0–5, with Phase 0 = harness and replication.

## 2. Overall verdict

The framing is right, the instinct to measure by intervention is right, and the previous session was honest about failures. The engineering is competent for a compute-starved sandbox.

But the evidence is weaker than the report reads, for structural reasons rather than seed noise. Three findings change what should happen next. They are ordered by how much they matter.

---

## 3. Finding 1: the synthetic testbed cannot test the goal **[verified]**

The generator has 4 modes and 12 content tokens. Modes repeat/succ/pred are fully determined by the first content token; copy2 by the first two. So the number of distinct sequences is 3×12 + 144 = **180**. With 20,000 training sequences each one is seen about 110 times.

Running the generator with the handoff's seeds: 180 unique training sequences, 167 unique test sequences, and **all 167 appear in the training set**. The "held-out" evaluation is on memorized data.

Consequences:
- A 2-layer transformer with position embeddings and 16 positions can solve this as a lookup table. Features like `mode=repeat & cur=10` may be table rows, not rules.
- Every ablation, legibility, and invariance number is measured on memorized inputs.
- The project's actual goal, predicting behavior on *untested* inputs from mechanism, is untestable on this bed. Nothing so far bears on it.

The plan already calls for a new testbed in Phase 0c. It should be Phase 0a, before replication. Replicating memorization numbers across five seeds is the most expensive way to learn the least.

What the new testbed needs, from first principles: the input space must be combinatorially larger than the training set, the generating mechanism must be known and compositional, and there must be held-out splits that require the mechanism (unseen start tokens, unseen mode×token combinations, longer sequences, rules composed in unseen orders). Stochastic rules are a good addition but generalization is the non-negotiable property.

## 4. Finding 2: the faithfulness metric mostly measures something true by construction

The readout is linear in the final code, so a feature's contribution to the target logit is `code_f × W[f, target]`. Ranking active features by that contribution and ablating the top three must lower the target logit. That is arithmetic, not evidence about mechanism. A dense transformer with a sparse autoencoder bolted onto its last layer passes the identical test.

The sufficiency test (keep only top-3) is more informative, but it too only concerns the last layer → logits step. Nothing quantifies faithfulness of the *path* through layers 0..L−1, which is the only thing "by construction" adds over post-hoc sparse autoencoders. The recursive trace exists but was run on one example and never scored.

Smaller problems in the same metric:
- The random-3 control is drawn from all 8 active features, so it overlaps the top-3 in 82% of samples **[verified]**. This shrinks the gap rather than inflates it, but it is a sloppy control.
- Completeness above 1.0 (1.10 on synthetic, 1.18 on text) is reported as "three features explain 118% of the logit". It means the other active features push *against* the answer. Cancellation between features is a legibility red flag, not a success.
- The magnitude-ablation control was written into `run_job.py` but never run.

What to add:
1. **The missing null model.** Train the dense baseline, fit post-hoc sparse autoencoders at every layer boundary with the same F and k, and run the identical metric suite. Every gate in the plan should be "beats the post-hoc baseline on path faithfulness at matched tax", not an absolute number.
2. **Path-level faithfulness.** For each prediction, compute the traced circuit (the set of layer/position/feature nodes), ablate everything *not* in the trace, and report the retained log-prob distribution. That is the sufficiency test for the explanation, not for the last layer.
3. Exclude the top set from the random control; report per-example distributions, not just means.

## 5. Finding 3: "complete, no side channel" is overstated

Five channels exist that the code does not name:

1. **Magnitudes.** k continuous non-negative numbers can carry arbitrary information. The handoff notes this as a future audit. It should be the first audit, because it is cheap and decisive: at eval time replace each active activation with that feature's mean activation and measure the NLL change. The change is the information carried by magnitudes.
2. **Overcomplete dictionary.** F = 128 directions in d = 64 dimensions cannot be orthogonal. The tied encoder `relu(h·Dᵀ)` therefore responds to a "pure" feature f on every feature g with positive overlap. Superposition is capped at k active features; it is not removed.
3. **Rank-limited readout.** The readout is `W = D·out`, rank ≤ d = 64 < F = 128. At most 64 features can have linearly independent votes. This is a plausible cause of the observed "next=5 or next=7 depending on mode" polysemantic outputs, and it is a design choice, not a training accident.
4. **Attention patterns.** Which position was attended is a continuous state computed from dense Q/K and is not in the code. The plan's Phase 2 addresses this.
5. **Dense round-trip.** In v3 each layer still decodes the code to a dense vector, runs a dense block, and projects back. The *state* is nominally sparse; the *computation* is dense, and d exists only because transformers have it. You already flagged this as an industry pattern. Phase 1 addresses it.

Two cheap experiments follow directly:
- **Named-neuron baseline.** Set F = d with an orthogonal (or fixed identity) dictionary, i.e. top-k sparsification of the residual stream with no learned dictionary at all. This is the simplest possible legible interface. If it matches v1/v3 on the metrics, the dictionary is buying nothing and should go.
- **Dictionary interference.** Report the distribution of off-diagonal |D·Dᵀ| entries. If features overlap heavily, the "one direction, one meaning" claim is false in practice.

## 6. Smaller code and metric issues

- **v3 AuxK reconstructs the wrong target.** In the code-residual branch the aux tuple stores `(h + upd) − h`, which is just `upd`. Dead features are asked to reconstruct the entire dense update rather than the part the sparse write missed. The consistent target is `upd − delta·D`. Inconsistent with v1/v2 and biases dead features toward whole-update directions.
- **Layer-invariance metric counts noise.** A feature whose best F1 is 0.30 at one layer and 0.32 with a different label at another counts as "changed meaning". It never had one. Restrict to features that are clean (F1 > 0.8) at at least one layer. Also, in v3 persistence copies features forward unchanged, so invariance is partly tautological; separate "carried" from "recomputed".
- **Clean-feature percentage has a moving denominator.** Live counts went 97 → 117 → 124 across v1/v3/v3-kw4. Report counts alongside fractions.
- **Predicate set misses the copy2 cause.** For copy2 the next token equals `prev`, so the true cause is `mode=2 & prev=v`. That conjunction is not in the predicate set, so the copy2 mechanism can never score as clean.
- **Text legibility numbers are not interpretable.** With char-only predicates, "2–5% clean" says almost nothing about the model. Better to report "unmeasured pending intervention-defined legibility" than a number that reads as a result.
- **Circuit trace is dominated by persistence edges.** The example trace shows `bn1 pos8 f8` as the parent of `bn2 pos8 f8` with effect equal to the full activation. That is the residual carrying the feature, not a computation. The trace should label carried edges separately and follow them to the layer that originally wrote the feature.
- **Text comparison confounds.** One seed, batch size 32, different convergence rates; acknowledged in the handoff. Add a matched-capacity dense control too (a dense model whose residual width equals k, not d).

## 7. Review of the Phase 0–5 plan

**Keep.** Rules as the primitive; routing as lookup with provenance; persistence; anneal dense → sparse → snap → verify hard reproduces soft; multi-seed; intervention-defined legibility; time-boxing.

**Reorder Phase 0.** New order: (a) generalizing testbed with shift splits; (b) the three controls: post-hoc SAE null model, magnitude-binarization audit, named-neuron baseline; (c) path-level faithfulness metric; (d) *then* replicate v3 across seeds, only if it still looks better than the controls; (e) then Phase 1. Replication-first would spend the most compute on the least informative question.

**Make description length a gate, not an audit.** Phase 1's fan-in-3 rules over F features is a combinatorial search. Annealing from dense is the right trainability approach, but the capacity question is separate: how many rules does it take to match dense perplexity on text? If the answer is 10⁵, each rule reads fine and the system is still illegible. Measure rules-needed vs perplexity as a curve early, on the small text config, and set a budget.

**Re-state P2.** "A small fixed set of nameable units" conflicts with your open-Ω question. The intervention-defined version already proposed is better: every unit has a description that predicts, on held-out data, when it fires and what ablating it does. Make that the legibility metric from day one, on synthetic as well as text, because it is the only version that transfers to real data.

**Add a third layer operation: decide.** The plan says a layer must only compute and route. The readout is a third operation and v4 shows it is not free. Rather than learning a sparse readout (which starved gradients because the model had to search for *which* token each feature votes for), fix the assignment: the last layer must produce `next=v` features, one per vocabulary item, with a fixed identity readout. The search that killed v4 disappears because the assignment is given. This makes the last layer's meaning known by construction and is worth one time-boxed attempt.

**Add a null hypothesis to every gate.** Each phase gate should compare against the dense + post-hoc analysis baseline at matched tax. Absolute numbers on a memorizable task are what produced the current over-reading.
